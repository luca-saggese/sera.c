# Correctness debt

Open correctness items that are deliberately deferred. Each entry records the
exact observed failure, the evidence, and the milestone at which it must be
resolved. Integration-level success (no crash, no NaN, finite logits) is
tracked separately from numerical correctness.

---

## D1 — M2 semantic canary argmax mismatch (q01)

**Status:** OPEN — deferred to the native Q4_K/Q6_K correctness pass.

**Milestone:** M2 integration PASS, correctness DEFERRED.

**Observed (T=137, real workload, `--forward`):**

```
./q3 --forward models/Qwen3-32B-Q4_K_M.gguf \
      --tokens /tmp/can_q01.bin \
      --candidate-token-ids 11650,11453,1151 --json
```

```
candidate_token_ids : [11650, 11453, 1151]   ("gray", "black", "red")
candidate_logits    : [-0.005052, 0.172533, -0.096292]
candidate_argmax    : 11453                  ("black")
expected_index      : 0                      ("gray")
```

**Failure:** the argmax is index 1 instead of the expected index 0. The logits
are finite and of comparable magnitude (spread ~0.27), so this is a numerical
divergence, not a NaN/Inf or a layout blow-up.

**What is already ruled out:**

- The MMQ arena sizing bug is fixed: the run no longer aborts with
  `q3 pool: workspace exhausted`. Root cause was `max_features` being taken
  from `config->vocab_size`, which is legitimately 0 for this GGUF (no vocab
  key), collapsing the arena back to its fallback floor. It now comes from the
  bound `weights->output.n`.
- The Q6_K MMQ Q8_1 layout bug is fixed (`e5a907b`): the activation
  quantization is keyed on the real weight type, so Q6_K no longer reads
  `d4[]` where `ds4[]` was written.
- M1 Q4_K linear parity against the CPU oracle passed at M=1/4/16.

**Not yet established:** whether the divergence originates in the Q4_K/Q6_K
dequantization, the RMSNorm, RoPE, the attention/KV path, or the LM head. The
M2 diagnostics that would localize it (layer-0 parity, KV equivalence,
per-layer NaN scan) were intentionally not run in this pass.

**Resolution gate:** the native Q4_K/Q6_K correctness pass, where the
dequantized oracle is re-enabled and the full forward is compared against it.
Until then, M2 is integration-complete only.

**Reproduce:** the token file `/tmp/can_q01.bin` is 137 raw uint32 LE tokens
(129 state tokens + the q01 suffix). It is regenerated by
`tools/tokenize_workload.py` from `docs/research/m3/workload_tokens.json`.
